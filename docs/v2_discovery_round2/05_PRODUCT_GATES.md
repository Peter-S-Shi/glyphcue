# V2 产品门与决策状态

日期：2026-10-03。本文把用户已决定的产品政策、仍需证据的工程门和发行门分开。它不是冻结批准记录。

## 已关闭的方向门

| 门 | 当前决定 | 仍需验证的部分 |
|---|---|---|
| PG-01 隐私路由 | ASR 必须本地；翻译/TTS 本地优先，外部服务只能由用户明确选择并显示 provider、端点、数据范围、条款和费用；禁止静默云回退 | 各 BYOK adapter 的具体条款与界面文案 |
| PG-02 语言边界 | EN/ZH/FR 是首轮锚点，不是永久上限；领域和接口必须可扩展 | 六个锚点翻译方向、声线、对齐、字体和质量结果 |
| PG-03 配音边界 | V2.0 最低闭环为一条获得许可的预设合成声线、单旁白；不做克隆、自动多角色、唇形同步、源说话人分离 | 声线、音频时长和混音的验收 |
| PG-04 绿地重构 | 不做 V1 数据迁移、UI 兼容或旧领域保留；只在独立审查后复用工具和测试经验 | 复用清单与安全审计 |

## 保持开放的发行与质量门

| 门 | 决策问题 | 通过证据 |
|---|---|---|
| PG-05 Windows 运行时 | Qt/QML、Tauri、Electron、WPF/WinUI 中哪条路线进入实现 | 同一交互切片、进程取消、干净离线安装和媒体预览实验 |
| PG-06 硬件档位 | CPU、NVIDIA、AMD、Intel 的首发支持范围及最低内存 | 固定模型/量化/驱动的安装、冷启动、吞吐、OOM、恢复报告；成功一次不等于全系列支持 |
| PG-07 语言质量 | 哪些 stage/language pair 可标为产品已验证 | 有参考转录的短集、人工错误与修订时间、时间边界、导出和离线证据 |
| PG-08 许可与分发 | 精确 runtime、权重、声线、字体、FFmpeg build 是否可商用捆绑 | revision、来源、哈希、许可证、通知、源码/替换义务和发行包审计 |
| PG-09 资源交付 | 模型是应用内、按需下载还是用户自带 | staging 校验、断点/失败恢复、离线重启、旧版本保留和删除行为 |
| PG-10 外部服务 | 是否接入某个翻译或 TTS provider | 用户主动确认、最小数据发送、地区/留存/商业条款和失败/计费说明 |

PG-05 与 PG-06 不阻止先写产品契约；它们阻止把候选框架或硬件能力写成发行承诺。PG-07 也不要求三语全部达标才设计编辑器，但没有通过的 stage 必须在界面中显示为未验证或不可用。

## 冻结判定

本轮研究完成后，可以评审“产品范围是否冻结”。冻结应至少确认：核心闭环、可选阶段、明确排除项、数据不出本机政策、单旁白配音基线、失败和修订语义。框架、模型、最低硬件和商业发行清单仍可作为实现前门；本文件不替用户批准它们。
