# GlyphCue V2 设计范围契约（草案）

状态：供 Claude Code Design 评审。它描述产品行为和边界，不锁定 UI 框架、模型名称或代码结构。

## 产品承诺

用户将本地视频或音频交给 GlyphCue，在本机生成带来源和时间证据的可编辑源文字；用户可校订时间和文本，按需要生成双语字幕、单旁白配音，并导出软字幕、字幕文件、音频或烧录字幕成片。核心 ASR 不依赖网络。

## 核心工作区

1. **项目与媒体**：选择文件、识别音轨、显示媒体身份、时长和可处理性；原文件只读。缺失或移动后要求重新定位并核验内容。
2. **识别与证据**：选择本地资源、语言提示和音频范围；显示准备、运行、取消、失败、待资源和已提交状态。保留原始识别结果，允许重新运行而不覆盖人工版本。
3. **源文字编辑**：按 cue、时间轴和媒体播放定位编辑文本、拆分、合并和调整时间。显示估计时间与人工确认的区别；编辑以修订保存，可撤销并能回看来源。
4. **字幕与翻译**：为目标语言建立明确的有向翻译修订；显示模型/服务、版本、时间和未验证能力。用户可逐句锁定、修改、重做；锁定内容不能被后台结果覆盖。
5. **配音与音频**：选择获许可的预设声线，生成单旁白脚本和音频 take；用户可调整分段、间隔、增益和混音策略。配音文本与显示字幕可以不同，但必须有来源关系。
6. **导出**：选择字幕格式、音轨、字体/样式、软字幕或烧录、输出容器和目标路径。导出基于明确快照；完成后显示实际文件、时长、校验和失败原因。

这些是逻辑工作区，不规定导航、面板排列或视觉设计。播放预览可在工作区间共享，但最终烧录预览须使用与导出相同的字幕排版和字体资源。

## 状态、资源与网络

每个项目阶段均能显示 `未安装 / 下载中 / 校验中 / 就绪 / 不兼容 / 损坏 / 加载中 / 内存不足 / 有更新`。模型、运行时、字体、FFmpeg 与应用壳分别记录版本、哈希、许可和来源；下载先进入临时区，完整校验后才切换。

默认操作不上传媒体或文本。外部翻译/TTS 必须由用户显式选择，确认发送的文本、provider、地区、条款和可能费用；失败不得自动换云端。断网时已安装的本地核心流程应能启动并给出缺件原因，而不是卡在无意义的网络重试。

## 失败、取消与修订

任务可排队、准备、运行、校验、提交、完成、取消中、已取消、失败或中断。取消只有在进程树确实退出且迟到结果被拒收后才算完成。应用崩溃或关闭后，已提交产物保留；未提交任务标为中断，可从完整阶段重试。

生成结果绑定输入修订、资源版本和配置。用户后来编辑时，旧结果可作为过期候选保留，但不能覆盖新文本；样式改变只使布局/导出失效，文本改变可使翻译、配音和相关对齐失效。人工锁定保护用户结果不被覆盖，也不隐藏其过期状态。

## 可扩展性与明确延后

语言使用可扩展的 BCP 47 标签和分阶段 capability，不把 EN/ZH/FR 写成永久枚举。首轮验收锚点为三语及六个有向翻译对；扩展语言必须分别取得 ASR、翻译、声线、对齐、字体和导出证据。

延后到 V2.0 之后：说话人克隆、自动多角色配音、唇形同步、源说话人分离、云端 ASR、无证据的全语言承诺、网络协作、插件商店、分布式任务平台、V1 数据自动迁移。标准字幕导入可作为低成本入口，但不能替代本地 ASR 主流程。

## 设计验收问题

设计稿必须能回答：用户如何知道某阶段尚未验证；如何比较和恢复修订；锁定后如何处理新结果；取消和重启怎样反馈；断网、缺模型、OOM、媒体移动和导出失败怎样继续；如何明确看到本地处理与外部发送边界。契约通过后，技术实验只决定实现路径，不应悄然扩大产品范围。
