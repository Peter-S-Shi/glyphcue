# GlyphCue V2 最小可行性实验计划

日期：2026-10-03。本文只定义后续实验，不执行下载、安装、模型推理或生产实现。所有阈值是建议的筛选门槛，需在 Product Gate 关闭后确认。

## 实验原则

- 使用获授权、可公开或合成的材料；不把私有媒体拷入仓库或实验产物。
- 三种语言都测：英语、中文、法语。六个翻译方向分开记录，不用平均数掩盖 ZH↔FR 或 FR↔ZH 的问题。
- 固定硬件、模型 revision、量化、线程、解码参数和输入范围；每轮只改变一个主要变量。
- 记录原始输出、人工参考、时间戳和资源指标，保留 provider/model/runtime/license manifest。模型榜单、README 速度和 UI “成功”都不是验收结果。
- 先做短样本决策实验，再做长文件稳定性与发行实验。任何候选没有通过质量与许可双门槛，都不能进入默认包。

## E1：三语本地 ASR

材料：每种语言至少三段约 60–90 秒（清晰独白、噪声/音乐、专名/数字/混语），另加一段约 20 分钟长片。每段需要人工听校文字和人工段边界。

比较顺序：Media Downloader 的 faster-whisper/CTranslate2 base 或 small 作为基线；whisper.cpp 对应量化路线作为 Windows/非 NVIDIA 对照；只有基线不足时才加入更大 Whisper 或 Qwen3-ASR。记录 WER/CER、整句遗漏/幻觉、段边界误差、RTF、首段延迟、峰值 RAM/VRAM、backend、冷/热启动和模型磁盘占用。

建议初筛：干净语音 EN/FR WER ≤ 10%、ZH CER ≤ 10%；困难材料按类别报告，不以综合平均通过；不出现整段凭空生成；30 个标注 cue 的边界误差 P95 ≤ 500 ms。速度阈值按 PG-03 目标机器确认。

## E2：对齐是否值得进入默认链

仅当 E1 原始时间戳达不到编辑体验门槛时执行。每种语言选 10 条包含数字、货币、专名的 cue，比较 ASR 原始词/段时间、WhisperX 和 Qwen3-ForcedAligner 中一个挑战者。记录边界误差、无时间词率、额外模型与下载、峰值内存和人工修时。

建议门槛：P95 ≤ 300 ms 且全部词/字缺失都可见；若额外对齐没有明显减少人工修时，保持可选适配器，不放入核心默认链。Forced alignment 不能修复原始转录不存在的内容，也不能把译文直接对齐到原语音。

## E3：六方向字幕翻译

每个方向 20 条连贯 cue，包含术语、数字、代词、跨 cue 上下文和断句。比较一个 4B 与一个 7B/8B 的本地模型；云端只在 PG-01 明确允许后做对照。请求带稳定 cue ID、有限上下文和术语表，模型只返回目标文本。

验收记录：100% cue ID 与源时间保留；无整句漏译或新增事实；术语约束 ≥ 95%；每方向双盲语义中位数 ≥ 4/5；人工修改率、延迟和资源单独列出。失败只重试选中块，不能覆盖源文或已锁定译文。

## E4：三语 TTS 与片段时长

每种目标语言至少 10 条短、中、长文本，包含专名、数字、问句。比较 Kokoro 与 Qwen3-TTS 1.7B 预设声线；0.6B 只在资源预算需要时加入。确认每一声线的语言、许可、G2P 和依赖，不用根仓库许可证代表音色权利。

记录自然度/清晰度、数字与专名读法、漏读、实际时长、首尾静音、峰值、冷启动和资源。建议每语人工中位数 ≥ 4/5；至少 90% 句子在少量口语稿调整和 0.85–1.15 倍速范围内适配目标窗口，其余必须显式标记人工处理。此范围是待确认的工程起点，不是行业保证。

## E5：FFmpeg 成片与离线交付

用同一段约两分钟的合成三语材料，覆盖横/竖画面、Unicode 文件名、双语 ASS/SRT、可关闭字幕轨、永久烧录、目标配音音轨。验证字幕布局、字体、首尾时间、A/V 漂移、原音模式、失败清理和源文件保护。

冷安装后断网重跑本地 ASR、翻译、TTS 和导出；模型下载是单独的显式阶段。每个最终二进制记录来源、SHA-256、`-version`、`-buildconf`、`-L`、第三方库、对应源码和通知。建议首尾累计漂移 ≤ 100 ms，失败不覆盖源文件，缺模型/字体/编码器时明确失败。

## E6：任务恢复与隐私回归

注入取消、断网、坏模型、缺 tokenizer、OOM、FFmpeg 中止、应用重启和输出目录不可写。确认阶段状态、错误、已完成片段、重试范围和 derived artifact 过期规则；后台 native 调用不能假报立即取消。检查日志/项目包没有密钥、完整字幕或绝对本机路径泄露；云适配器只在用户明确启用时发送其声明的数据类别。

## 通过顺序

先关闭 PG-02/PG-03，运行 E1；只有 E1 通过才运行 E2。PG-01 与 PG-05 明确后运行 E3，并逐方向评审。PG-04 明确配音交付语义后运行 E4，随后 E5 验证成片；E6 可与 E1–E5 的工程 harness 并行，但不替代质量测试。

实验只负责筛选技术和锁定可交付边界。通过实验不会自动批准模型商业分发、云服务合同、声线权利、字体或编解码专利；这些仍需发行审计和产品决定。
